    Hub 目標架構

    狀態：規劃中

    Hub 是一座輕量 K8s，負責 GitOps、Policy、SSO 和可觀測性，並統一管理底下的 OpenShift 叢集。Hub 本身嚴格執行 Policy；底下的 Lab 叢集只稽核。

    元件

    需求 元件 部署在 說明
    叢集 k3s，3 個 server 節點（內建 etcd） ESXi 192.168.2.200 上的 3 台 VM 用 Terraform vSphere provider 建立
    API 高可用 kube-vip Hub API VIP 192.168.72.5
    LoadBalancer MetalLB（L2 模式） Hub Pool 在 192.168.73.0/24，同一個 VLAN，不需要 static route
    GitOps Argo CD + ApplicationSet Hub Hub 用 app-of-apps 管自己；push 模式管理 OCP
    Policy Kyverno + Policy Reporter Hub、OCP Hub 設 Enforce，OCP 設 Audit
    可觀測性 Prometheus、Loki、Grafana Hub 收 K8s audit log 和 SSO 登入事件
    SSO Authentik，上游接 GitHub org Hub 依 GitHub team 對應權限；Argo CD、Grafana、OCP 都改用它
    服務入口 Homepage Hub 服務清單
    憑證 cert-manager + Cloudflare DNS-01 Hub 內網服務也拿得到正式憑證
    Secret SOPS + age Git Git 裡不放明文 secret
    備份 Velero + etcd snapshot → NAS（NFS） Hub

    緊急存取：k3s 保留本機 admin kubeconfig，Argo CD 保留本機 admin 帳號（平常停用），GitHub 或 Authentik 出問題時使用。

    網段：VLAN 72 · 192.168.72.0/22 · Z-HUB · DHCP 關閉

    範圍 用途
    192.168.72.1 Gateway（UDM）
    192.168.72.5 k3s API VIP（kube-vip）
    192.168.72.10 – .12 k3s server 節點
    192.168.72.20 – .49 Hub 上的 infra VM（預留）
    192.168.73.10 – .250 MetalLB pool；192.168.73.10 固定給 Ingress
    192.168.74.0/23 預留，之後搬過來的服務

    網域：Hub 服務統一使用 *.hub.example.com。內網由 NAS 上的 AdGuard 做 DNS rewrite，指向 Ingress 192.168.73.10；憑證用 Cloudflare DNS-01 申請 wildcard。

    防火牆（Z-HUB 進出）

    來源 → 目的 內容 原因
    Z-LAB → Z-HUB 全通 OCP 預設可以連到 Hub 的服務（OIDC、log、registry mirror）
    Z-HUB → Z-LAB TCP 6443 → OCP API Argo CD 用 push 模式部署
    Internal → Z-HUB 全通 管理用
    Vpn → Z-HUB 全通 和 Z-LAB 一致
    Z-HOME → Z-HUB TCP 443 → Ingress 瀏覽器登入 SSO 和各服務
    Z-HUB → Internal DNS、NTP、NFS → NAS NFS 給 Velero 備份
    Z-HUB → External 允許 GitHub、container registry、Cloudflare API

    OCP 登入不需要放寬 OCP 的出口白名單：OCP 的 OAuth server 連的是 Hub 的 Authentik，只有 Hub 需要連 GitHub。OCP 上的 Kyverno 要拉 image，建議在 Hub 架 registry mirror（例如 Harbor 的 proxy cache），OCP 透過 Z-LAB → Z-HUB 拉取。

    SSO 登入流程（以 OCP 為例）

    sequenceDiagram
    participant U as 使用者
    participant OCP as OCP OAuth
    participant AK as Authentik（Hub）
    participant GH as GitHub
    U->>OCP: 開啟 console
    OCP->>AK: 轉址到 OIDC 授權端點
    AK->>GH: GitHub OAuth 登入
    GH-->>AK: 使用者和 team 資訊
    AK-->>OCP: ID token（groups = GitHub team）
    OCP-->>U: 登入成功，依 group 對應 RBAC

    兩座 OCP 的管理範圍

    叢集 Argo CD 部署內容 原因
    OCP 4.16 完整的應用部署 CD 部署目標
    OCP 4.20 只放共用基準設定（Kyverno、OAuth、log 傳送） 會常常拆掉重建

    建置階段

    階段 內容
    H0 UniFi 加 VLAN 72 和 Z-HUB policy（Terraform）；在 ESXi 192.168.2.200 建 3 台 VM
    H1 k3s、kube-vip、MetalLB、cert-manager、Argo CD（app-of-apps）
    H2 Authentik 接 GitHub；Argo CD、Grafana 改用 SSO
    H3 Kyverno（Hub Enforce）、可觀測性、Velero
    H4 註冊兩座 OCP；OCP Kyverno 設 Audit；OCP OAuth 接 Authentik；registry mirror
    H5 逐步把服務搬到 192.168.74.0/23
